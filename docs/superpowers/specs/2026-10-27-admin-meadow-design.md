# Admin Meadow: ทำให้หลังบ้านเป็นธีมเดียวกับฝั่งผู้เข้าร่วม

**วันที่:** 2026-10-27 · **สถานะ:** รอเจ้าของรีวิว · **ทำต่อจาก:** meetup ping (feature/meetup-ping)
**อ้างอิงธีม:** `docs/superpowers/specs/2026-10-26-meadow-match-design.md` (Meadow / สมัชชาสุขภาพครั้งที่ 19)

## เป้าหมาย

หลังบ้าน (`/admin` ทั้ง 18 หน้า) ต้องดูเป็นงานเดียวกับโปสเตอร์และมือถือผู้เข้าร่วม คือท้องฟ้า ทุ่ง กังหันลม และบล็อกสี "สังคม อยู่ ดี มี พลัง" แทนธีมอวกาศสีเข้ม "Mission control" ที่ใช้อยู่ตอนนี้ ฟังก์ชัน สิทธิ์ และข้อมูลทุกอย่างต้องเหมือนเดิม งานนี้เปลี่ยนแค่หน้าตาและข้อความ

**สำเร็จเมื่อ:**
- ทุกหน้าใน `/admin` ใช้สีและพื้นผิวจาก token ของ meadow และไม่เหลือพื้นผิวสีเข้มหรือสีที่ hard-code ไว้
- ตัวหนังสือที่มองเห็นได้ทุกตัวมีขนาดอย่างน้อย 16px ปุ่มและช่องกรอกสูงอย่างน้อย 44px และ contrast อย่างน้อย 4.5:1
- `/admin/live` เป็นฉากทุ่งเต็มจอ อ่านได้จากท้ายห้องเมื่อฉายขึ้นจอ
- หน้าผู้เข้าร่วมกับ `/print` เหมือนเดิมทุกพิกเซลที่เกี่ยวข้อง

## สิ่งที่เจ้าของตัดสินแล้ว

| เรื่อง | ตัดสิน |
| --- | --- |

| /admin/live | ใช้ฉากทุ่งเต็มจอ ตัวหนังสือใหญ่สำหรับฉายขึ้นจอ |

## 1. โครงสร้างธีม

- **สวิตช์ธีม:** `themeClassFor(pathname)` คืนค่า `"meadow meadow-work"` สำหรับ `/admin` และเส้นทางย่อยทั้งหมด ส่วน `/print`, `/journey` และ `/brand-preview` ยังไม่ใช้ธีมเหมือนเดิม ต้องปรับชนิดค่าที่คืนและเทสต์ใน `src/lib/theme.test.ts` ให้ตรงกัน คลาสนี้ใส่ที่ `<html>` ตั้งแต่ฝั่งเซิร์ฟเวอร์ ทำให้ portal อย่าง toast, dialog และ drawer ได้สีของธีมตั้งแต่แรกโดยไม่กะพริบ
- **ระบบ meetup ต้องไม่ทำงานในหลังบ้าน:** ตอนนี้ `meetup-context`, `meetup-card-host` และ `find-mode` ใช้ `themeClassFor` เพื่อเช็กว่าเป็นหน้าผู้เข้าร่วมหรือไม่ ให้เปลี่ยนไปใช้ฟังก์ชันใหม่ `isParticipantRoute(pathname)` แทน เพราะถ้าไม่เปลี่ยน พอหลังบ้านได้คลาส `meadow` ระบบ meetup จะเริ่มดึงข้อมูลในหลังบ้านด้วย
- **`theme-color` meta:** ใช้ค่าสีฟ้าเดียวกับฝั่งผู้เข้าร่วมเมื่ออยู่ใน `/admin`
- **ชั้นความหนาแน่น** `html.meadow-work` อยู่ใน `src/meadow.css` และปรับแค่ขนาด ไม่เพิ่มสีใหม่:
  - เนื้อความ 17px ตาราง 16px หัวข้อ 22–28px และห้ามมีตัวหนังสือที่มองเห็นได้เล็กกว่า 16px
  - ปุ่ม ช่องกรอก และ select สูงอย่างน้อย 44px แถวตารางสูงอย่างน้อย 48px โดยลด padding ลง
  - กฎ 20px ของฝั่งผู้เข้าร่วมใช้เฉพาะเมื่อไม่มี `meadow-work` เพื่อให้ฝั่งผู้เข้าร่วมไม่เปลี่ยนเลย
- **สี:** ใช้ token ของ meadow ที่มีอยู่เท่านั้น (sky, card, ink, muted) และใช้ `BLOCK_TAG` (`src/lib/issue-colors.ts`) สำหรับบล็อกสีทั้ง 6 สี ค่า hex ที่ hard-code ไว้ใน `src/styles/admin-pages.css` (51 จุด), `admin.tsx` และ `admin.qr.tsx` ต้องเปลี่ยนเป็น token ทั้งหมด ยกเว้นสีในรูป QR ที่ต้องเป็นดำบนขาวเพื่อให้สแกนได้
- **การเคลื่อนไหว:** ลด `src/styles/admin-motion.css` ให้เหลือแค่ fade และ translate สั้นๆ ถ้าเปิด `prefers-reduced-motion` หรือมี `html[data-lowspec]` ต้องไม่มีอนิเมชันเลย

## 2. โครงหน้า: แถบข้าง หน้าเข้าสู่ระบบ และจอสด

### แถบข้าง (`src/routes/admin.tsx`)
- เป็นแผงสีขาวบนพื้นฟ้าอ่อน ด้านบนมีโลโก้และแถบบางที่ไล่สี 4 บล็อก "สังคม อยู่ ดี มี พลัง"
- เมนูมี 18 รายการ (รวมลิงก์ Journey) แบ่งเป็น 4 กลุ่มภาษาไทย และเอาป้าย "Mission control" ออก ชื่อเมนูยึดตามที่ใช้อยู่ตอนนี้ ส่วนชื่อที่เป็นภาษาอังกฤษให้แปลเป็นไทย
  - **ภาพรวม:** ภาพรวม, จอสด, แผนที่
  - **ผู้คนและคู่:** สมาชิก, คู่เชื่อม, คำมั่น/ปฏิทิน, ไอเดีย, ผลงาน
  - **ข้อมูลและไฟล์:** นำเข้า CSV, ส่งออกข้อมูล, QR/ป้าย, สำรองข้อมูล, นโยบายสำรอง
  - **ระบบ:** บันทึกการใช้งาน (เดิมคือ "Log การใช้งาน"), ประวัติการแก้ไข, สรุปค่าใช้จ่าย, ตั้งค่า, เส้นทางทุกหน้า (เดิมคือ "Journey ทุกหน้า")
- หน้าที่เปิดอยู่มีแถบสีด้านซ้าย ตัวหนา และ `aria-current="page"`
- บนมือถือคงพฤติกรรมเปิด/ปิดแบบเดิมไว้ เส้นทาง สิทธิ์ และการซ่อนเมนูตามบทบาทต้องเหมือนเดิมทุกอย่าง

### หน้าเข้าสู่ระบบ (`AdminLogin` ใน `admin.tsx`)
- แบ่งเป็นสองคอลัมน์ ซ้ายใช้ `MeadowScene` (`src/components/meadow-scene.tsx`) พร้อมหัวข้อ "หลังบ้าน คนส. CoNnextS" และคำอธิบายสั้นๆ ภาษาไทย ขวาเป็นการ์ดสีขาวที่มีฟอร์ม
- บนมือถือเป็นคอลัมน์เดียว ฉากทุ่งเหลือแค่แถบด้านบน
- เอา `MissionVisual` และข้อความ "Network operations / 01" กับ "Authorized access" ออก
- ป้ายช่องกรอกขนาด ≥16px ข้อความ error ขนาด ≥16px และใช้ `role="alert"` ปุ่มเข้าสู่ระบบสูง 48px
- ตรรกะการเข้าสู่ระบบ บทบาท และ `admin-role-note` ต้องเหมือนเดิม

### จอสด (`src/routes/admin.live.tsx`)
- ใช้ `MeadowScene` เต็มจอเป็นพื้นหลัง
- ด้านบนมีตัวเลขใหญ่ 3 ตัว คือผู้เข้าร่วม คู่ที่เชื่อมแล้ว และความตั้งใจ แต่ละตัวอยู่ในการ์ดสีขาวที่มีบล็อกสีกำกับ ตัวเลขขนาด ≥64px ป้ายกำกับขนาด ≥28px
- ฟีดสดแบบไม่ระบุชื่อ (`buildFeed`) แสดงเป็นการ์ดที่มีตัวหนังสือ ≥28px และคง `RotatingPrompt` ไว้
- ออกแบบสำหรับ 1920×1080 และ 1280×720 โดยไม่ต้องเลื่อนจอ ถ้าเปิด reduced motion กังหันจะหยุดนิ่ง
- ยังไม่ระบุชื่อคนเหมือนเดิม เพราะขึ้นจอสาธารณะ

## 3. หน้าอื่นอีก 15 หน้า

- **พื้นผิว:** `card-soft`, `admin-workspace`, `admin-records` และ `admin-section-meta` เป็นการ์ดสีขาวบนพื้นฟ้า แก้ที่ CSS กลางก่อน แล้วค่อยแก้ class ในหน้าเฉพาะจุดที่จำเป็น
- **ขนาดตัวหนังสือ:** มี `text-xs`, `text-[10–14px]` อยู่ราว 160 จุดใน `src/routes/admin*.tsx` ทุกจุดต้องได้ขนาด ≥16px ทำได้สองทางคือยกที่ชั้น `meadow-work` หรือเปลี่ยน class
- **สถานะ:** ใช้บล็อกสีคู่กับไอคอน lucide หรือข้อความทุกครั้ง ห้ามสื่อด้วยสีอย่างเดียว
- **ตารางกว้าง** (people, logs, audit, costs, connections): เลื่อนแนวนอนได้ภายในการ์ด หน้าเองต้องไม่เลื่อนแนวนอน และหัวตารางติดอยู่ด้านบน
- **กราฟ** ในหน้า index และ logs: ใช้ชุดสีบล็อก โดยมีป้ายหรือ legend กำกับเสมอ
- **ข้อความ:** เปลี่ยนป้ายและ kicker ภาษาอังกฤษเป็นภาษาไทยที่อ่านง่าย คงคำเทคนิคที่ทีมงานคุ้นเคยไว้ เช่น CSV, QR, Backup โทนต้องอบอุ่น ไม่ตีตรา และไม่ใช้ภาษาเชิงทหารอย่าง "mission" หรือ "operations"
- **ห้ามเปลี่ยน:** handler, query, สิทธิ์, การยืนยันก่อนลบหรือนำเข้า, ชื่อไฟล์ส่งออก และ route ทั้งหมด

## 4. การตรวจสอบ

- **ภาพฐาน:** ก่อนเริ่มงาน ถ่ายภาพทุกหน้าในหลังบ้าน (รวมหน้าเข้าสู่ระบบ) ที่ 1440×900 และ 375×812 เก็บไว้ใน `.superpowers/sdd/<plan>/baseline/`
- **สแกนฟอนต์:** เพิ่มตัวเลือก `min` ให้ `scripts/qa/font-scan.js` โดยค่าเริ่มต้นยังเป็น 20 แล้วสแกนทุกหน้าและทุกสถานะที่เปิดได้ (dialog, ฟอร์ม, error) ด้วย `min 16` ที่ 1440 และ 375 ผลต้องได้ `small: []`, `clipped: []` และ `overflowX: false`
- **ฝั่งผู้เข้าร่วมไม่เปลี่ยน:** สแกน `/`, `/commitments` และ `/update` ด้วย `min 20` แล้วต้องผ่านเหมือนเดิม และ `/print` ต้องเหมือน `main` (เทียบผ่าน worktree ชั่วคราว)
- **การเข้าถึง:** contrast ≥4.5:1 ไล่คีย์บอร์ดผ่านแถบข้าง ฟอร์มเข้าสู่ระบบ และตาราง โดยโฟกัสต้องมองเห็นได้ และลองทั้งแบบ reduced motion
- **รีวิว:** ให้ผู้รีวิวอิสระตาม /oil-ui ดูหน้าเข้าสู่ระบบ หน้าภาพรวม และจอสด แล้วให้คะแนน
- **ความปลอดภัยของข้อมูล:** ตอนทดสอบใช้ข้อมูลจริงแบบอ่านอย่างเดียว ห้ามกดนำเข้า ลบ สำรองข้อมูล หรือบันทึกตั้งค่า ถ้าต้องดูสถานะเหล่านี้ให้ใช้ fixture ในเครื่องที่ไม่ commit
- **Gates:** `npx vitest run`, `npx tsc --noEmit -p .`, eslint บนไฟล์ที่เปลี่ยน (ต้องไม่มี error ที่ไม่ใช่ prettier) และ `npx vite build`

## นอกขอบเขต

- เปลี่ยนฟังก์ชัน สิทธิ์ หรือโครงข้อมูลของหลังบ้าน
- สร้าง component หรือ shell ใหม่ทั้งชุด (คือแนวทาง B ที่ไม่ได้เลือก)
- `/print`, `/journey` และ `/brand-preview`
- dark mode ของหลังบ้าน
